# Lithium — Project Instructions

## What is this?

Lithium is a custom desktop point cloud visualizer, annotator, and renderer. High-performance, GPU-accelerated, workstation-grade. Packaged as a standalone executable. Three modes carry the research workflow: **CONTACT_SHEETS** (browse a per-cloud gallery), **LIGHT_TABLE** (paint / refine per-point labels), **AUTOMATION / TRAIN** (stage datasets + train Pointcept PT-v3 models).

> The clinical product surface (**SpineLab** — IMAGING / HOLOGRAM / OVERWATCH, CT ingest, PolyPose registration, clinical measurement analytics) was split out into its own repository. Don't reintroduce imaging / registration / clinical-measurement code here.

## Tech Stack

- **Language:** Python 3.12
- **Rendering:** ModernGL (OpenGL 4.3+) with custom GLSL shaders
- **Window:** GLFW
- **GUI:** Dear ImGui (`imgui[glfw]`) — ultra-dark flat neutral grey theme; tokens in `src/gui/tokens.py`
- **Data:** laspy (LAS/LAZ), plyfile (PLY), numpy
- **Training:** Pointcept PT-v3 subprocess in conda env `lithium-ptv3`
- **Export:** Pillow (PNG)
- **Packaging:** PyInstaller (windowed — no stdout in the packaged build)

## Running

Linux:
```bash
source .venv/bin/activate
python -m src.main <path_to_ply_or_las_or_directory>
```

Windows:
```bash
source .venv/Scripts/activate
python -m src.main <path_to_ply_or_las_or_directory>
```

Or use the `run.sh` (Linux) / `run.bat` (Windows) launcher at the repo root.

## Project Conventions

- **GUI style:** ultra dark, flat neutral greys. Use semantic tokens from `src/gui/tokens.py` — do NOT push raw color tuples. Migration from `theme.py` is in flight.
- **Layering:** core ← data ← rendering/training ← gui ← main. No back-edges; no cycles. Mode constants belong in `src/core/modes.py` (not `src/main.py`).
- **GPU uploads happen once** — only uniforms change per frame.
- **Background threads** load files and run subprocess pipelines (PT-v3 training); the main thread polls futures and does GPU work. Never block the frame loop.
- **Subprocess reader threads must NOT mutate `app.*` directly.** Push events into a main-thread deque (see `_pending_label_applies` / the Pattern-A event queue in `src/main.py`, drained in the frame loop).
- **All subprocesses get `PYTHONIOENCODING=utf-8`.** Default cp1252 chokes on tqdm em-dashes and poisons ImGui frame state.
- **Labels are sacred** (`project_label_safety_priority`): every write goes through `apply_label` (undo) + atomic `tmp + os.replace` persist + length-mismatch guard. Errors must surface in the UI — `print()` is invisible in the packaged build.
- **Anchors are cloud-local.** Store `(cloud_key, local_pos)`, never world coordinates.
- **Reject scope creep** — research-mode software. Skip auth/audit/regulatory framing.

## Operational Gotchas

- **mm units everywhere** — point cloud coordinates are in mm; Pointcept `grid_size=0.5 mm` at `src/training/config_gen.py` (the upstream default of 0.001 m fails the depth ≤ 16 assertion on small objects).
- **`batch_size=2`** for PT-v3 — fits VRAM.
- **`extent / grid_size < 65536`** or Pointcept depth assertion fails.
- **3 modes** — CONTACT_SHEETS / LIGHT_TABLE / AUTOMATION. Mode integer values are 1 / 2 / 5 (preserved from the historical six-mode layout so persisted settings stay valid); the retired 0/3/4 indices left with SpineLab and are not reused. New features go into an existing mode unless they genuinely don't fit.
- **Single-instance lock** at `~/.lithium/library/.lock` — App refuses to start if another live instance owns it. Override the library dir with `LITHIUM_LIBRARY_DIR`.
- **The catalog *is* the dataset** — once a cloud is imported, its labels live under `~/.lithium/library/labels/<namespace>/<file_key>.npy` forever. There is no separate "save project" step.
- **Labels are namespaced per project (v2, 1.1)** — the namespace is a project id (or `_library` for non-project views). A cloud in N projects has N independent label arrays; painting in one never touches another. `cloud_store.set_active_label_namespace` is set by `App.set_active_view`; background workers freeze the namespace at submit. A 1.0 flat `labels/` tree migrates automatically on first catalog init (`migrate_labels_layout_v2`, marker-gated, non-destructive).
- **Model class maps are frozen at launch** — `TrainedModel.class_map` (+ a `classes.json` mirrored into the run's work_dir) is the authoritative record of output-channel meaning; inference resolves classes from the registry entry first.
- **SANDBOX (1.2):** pseudo-project `proj:sandbox` (`src/data/sandbox.py`): no ontology; inference results are cloud-level layers = label namespaces `layer:<model_id>` + `_layer.json`. Models from any project run in the sandbox; in normal projects only class-name-compatible models are offered (`_inference_eligible_models`).
